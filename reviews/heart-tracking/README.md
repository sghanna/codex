# Heart ownership and moon review

Open `index.html` through the repository HTTP server. Compare three proposed cues in the same valid practice hands: a heart capture, a moon threat, and a blocked moon. A shows everyone's heart count and queen ownership beside their cards. B names the most recent point taker. C explains moon status above the player's hand.

The comparison frames pause for inspection. Each “Try this hand” link opens a playable practice version, preserving the original four-second advance. The main game now advances immediately after collection and auto-plays a sole legal card after three seconds. The main game's saved progress is never read or changed. Practice keys start with `codex-hearts-tracking-`; the paused comparison and playable hand also have separate keys. Previews do not register a service worker.

Selected: A + C. The main game combines the aligned heart counts with the moon-status panel, with English, Spanish, and Vietnamese copy. These English prototypes preserve the separate original proposals. A playtest with Mom is still needed.

`fixtures.js` contains engine-validated hands generated by `build-fixtures.mjs`. `demo-app.js`, `game.html`, and the supporting game files in `assets/` are snapshots from before adoption. Keep them fixed so later main-game changes do not replace the original alternatives. `variants.js` derives ownership only from public completed tricks, including a pending completed trick. The blocked example deliberately has one heart owner and a different queen owner.

WebKit review covered all three options in all three situations at 390×740, 375×667, and 844×390. The moon panel moves beside the hand in landscape. Browser checks also verified asset loading, untouched main-game saves, and the playable countdown. A physical iPhone test is still needed.
